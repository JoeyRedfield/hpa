# ADR 0002：成长循环用「规则文件 + 回归样例」，而不是微调或向量记忆

## 背景

作业的元要求是：成功流程和**纠正**要沉淀成可读、可改、可复用的东西，新会话照样生效。
可选载体很多：微调模型、向量库写记忆、prompt 里堆历史对话、或让模型自由编辑配置文件。

## 决定

纠正固化成三种**人类可读、git 可审**的文本：

1. `rules/mail-triage.md`：分诊规则 DSL，`hpa mail triage` 每条邮件都会跑；
2. `rules/reply-style.md`：写作风格要求，`hpa process` 起草时注入；
3. `memory/preferences.md`：关于用户的事实与偏好，同样注入。

由 `hpa growth run` 让模型产出提案，脚本负责**校验后写入**：

- 目标路径白名单（只允许上面三个文件）；
- 规则必须先通过 DSL 解析，写坏就回滚整个文件；
- 每条改动带 `来源：纠正 #N` 注释；
- 可判定的规则同时生成 `tests/cases/*.md` 回归样例，`hpa growth check` 随时验证；
- 改动只在工作区，用户在 `git diff` 里审完再提交。

## 为什么不用微调 / 向量记忆 / 自动改配置

- 微调：慢、不可解释、纠正一条要重训，且与本项目「确定性流程 + 模型只管理解」的分工冲突。
- 向量记忆：能召回但**不改变行为**，下次仍可能犯同样的错；而且不可读、不可审。
- 模型自由改配置：无法回滚、可能写坏语法、沉默地扩大规则覆盖面（比如把所有邮件都标成要回）。
- 规则文件 + 回归样例：失败可复现、可 `git bisect`、可在新会话零成本加载，且样例失败会立刻暴露「规则被写宽了」。

## 代价

- 规则覆盖面受 DSL 表达力限制；复杂判断仍回落到模型分类。
- 需要用户审 diff（这正是「会成长」要人参与的部分）。

## 结果

`hpa growth run` → `git diff` → `hpa growth check` → commit；下一次 `hpa daemon`/`hpa process` 直接使用新规则。
